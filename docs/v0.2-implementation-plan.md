# SnapSafe v0.2 Implementation Plan

## Repository format and integrity

- [x] Versioned v2 head and snapshot manifests.
- [x] Streaming BLAKE3 file hashes.
- [x] Snapshot manifest hashes stored in the head manifest.
- [x] Hash-based snapshot reuse, diff, verify, and restore preflight.
- [x] Verified predecessor data before hard-link reuse.
- [x] Read-only stored files where supported.
- [x] Payload isolation under each snapshot's `data/` directory.
- [x] UTC timestamps with subsecond precision.
- [x] Stored file type, Unix mode, symlink target, and modification time.

## V1 migration

- [x] Automatic migration before every non-`init` command.
- [x] Hash each unique hard-linked physical file once per run.
- [x] Resumable prepared manifests and payload directories.
- [x] Validate resumed payloads before deleting legacy data.
- [x] Keep the v1 head until every snapshot is ready.
- [x] Commit the v2 head last.
- [x] Resume post-head validation, protection, and cleanup.
- [x] Normalize Windows-style legacy paths.
- [x] Handle legacy top-level `data` directories safely.
- [x] Prevent migrated ignore rules from hiding represented files.

## Filesystem safety

- [x] Validate snapshot IDs and persisted relative paths.
- [x] Reject absolute, parent-relative, drive-relative, non-UTF-8, and unsupported paths.
- [x] Reject ambiguous snapshot prefixes.
- [x] Reject symlinked repository, snapshot, and temporary roots.
- [x] Preserve supported symlinks without following them.
- [x] Preserve dangling and cyclic symlinks on Unix.
- [x] Reject unrestorable unknown symlink types on Windows.
- [x] Reject unsupported special files.
- [x] Prevent restore and prune from escaping managed roots.

## Atomic operations and recovery

- [x] Repository lock for mutating commands.
- [x] Staged snapshot creation.
- [x] Atomic manifest replacement.
- [x] Snapshot transaction markers.
- [x] Recover interrupted snapshot transactions.
- [x] Recover interrupted prune transactions.
- [x] Preserve prune trash if rollback is incomplete.
- [x] Serialize concurrent snapshot creation.

## Restore and automation

- [x] Full source integrity preflight.
- [x] Exact managed-tree restore.
- [x] Restore regular files, directories, symlinks, modes, and timestamps.
- [x] Remove managed entries absent from the selected snapshot.
- [x] Preserve `.snapsafe`, `.snapsafeignore`, and ignored paths.
- [x] Automatic recoverable backup before restore.
- [x] Restore dry-run plan.
- [x] Global `-y` and `--yes`.
- [x] Reject non-interactive destructive commands without `--yes`.
- [x] Treat EOF as rejection.

## CLI fixes

- [x] Strict snapshot version parsing and duplicate rejection.
- [x] Correct prune duration parsing.
- [x] Mutually exclusive prune, tag, and metadata actions.
- [x] Unicode-safe truncation.
- [x] Deterministic output ordering.
- [x] One snapshot resolver across commands.
- [x] Nonzero status for incomplete operations.
- [x] `snapsafe --version`.

## Quality and release

- [x] Unit and integration coverage for integrity, migration, restore, pruning, paths, symlinks, concurrency, and recovery.
- [x] Rust 1.85 minimum-version check.
- [x] Linux, macOS, and Windows CI tests.
- [x] Formatting, Clippy, tests, and package gates.
- [x] Committed lockfile and locked builds.
- [x] Tag and package version validation.
- [x] Target-qualified release archives.
- [x] Release checksums.
- [x] Updated README.

## Not included in v0.2

- Chunk-level deduplication.
- Content-addressed object storage.
- Compression.
- Encryption.
- Remote storage.
- Cryptographic signing.
